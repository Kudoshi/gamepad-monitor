# Instructions for AI coding agents

Read this file before changing anything in this repository. It covers how the project is laid out, how to build and test it, and the rules that keep it safe for the person whose PC and controllers you are working on.

## What this project is

**Gamepad Monitor** is a Windows desktop app (C#, .NET 9, WinForms, x64 only) that:

- lists every game controller on the PC,
- shows live inputs and report rate ("ping"),
- tests rumble,
- turns controllers on and off at the driver level (with a software USB replug),
- and can hide controllers from games through the optional HidHide driver.

There are no NuGet dependencies. Everything goes through Win32 P/Invoke.

## Repository layout

```
GamepadMonitor/
  GamepadMonitor.csproj   project file; <Version> drives the release number
  MainForm.cs             Program entry point (+ helper modes), all UI and painting
  Devices.cs              P/Invoke (Native), device tree scan, HID parsing, XInput, Sony rumble, enable/disable
  QuickToggle.cs          USB port cycle (software replug), HidHide wrapper, elevated helper dispatch
  app.ico                 app icon (generated by tools/make-icon.ps1)
docs/screenshot.png       README screenshot
tools/make-icon.ps1       draws app.ico with System.Drawing (run with Windows PowerShell 5.1)
README.md                 user-facing guide
AGENTS.md                 this file
```

Build output (`bin/`, `obj/`, `dist/`, `GamepadMonitor-release/`) is git-ignored. Never commit it.

## Key types

| Type | File | Role |
|---|---|---|
| `Native` | Devices.cs | All P/Invoke declarations (cfgmgr32, user32 Raw Input, hid.dll, xinput1_4, kernel32, setupapi, winmm). |
| `DeviceScanner` | Devices.cs | Walks the PnP tree (`CM_*`) and groups each physical controller into one `GamepadRow` (its "top" node plus child nodes). Also classifies the connection and names the controller. |
| `GamepadRow` / `DevNode` | Devices.cs | One controller, and one driver node. State properties: `Disabled`, `PendingDisable`, `PendingEnable`, `Hidden`. |
| `HidDevice` | Devices.cs | One HID gamepad interface. It is either fed by Raw Input (`WM_INPUT`) or, with `Direct = true`, read by its own `ReadFile` thread. Parses reports with `HidP_*`, decodes Sony "extended" Bluetooth reports by hand, and sends Sony rumble. |
| `RateStats` | Devices.cs | One-second sliding window of report timestamps; source of Hz, interval, jitter and worst gap. |
| `XInputMonitor` | Devices.cs | Polls XInput slots every ~1 ms on a background thread (probes empty slots only once a second). |
| `DeviceState` | Devices.cs | Enable/disable through SetupAPI `DIF_PROPERTYCHANGE`, the same call Device Manager uses. |
| `UsbPort` | QuickToggle.cs | Finds a controller's hub and port and power-cycles it (`IOCTL_USB_HUB_CYCLE_PORT`). |
| `HidHide` | QuickToggle.cs | Detects HidHide, reads its hide list, and drives `HidHideCLI.exe`. |
| `Privileged` | QuickToggle.cs | Actions that need admin. They run in-process when the app is elevated; otherwise the app re-launches itself with `runas` in helper mode. |
| `MainForm` | MainForm.cs | List, detail pane and live-inputs strip, all custom-painted. The frame timer runs at ~30 fps. |

### Command-line modes (`Program.Main`)

| Arguments | Purpose |
|---|---|
| *(none)* | Normal GUI. |
| `--dump <file>` | Writes a plain-text diagnostics report (detected devices, grouping, replug target, a 1-second direct-read test, XInput slots), then exits. **Use this to test detection without the GUI.** |
| `--set-state enable\|disable "<instanceId>"` | Elevated helper: change device state, then replug if the change is stuck. |
| `--replug enable\|disable "<instanceId>"` | Elevated helper: finish a pending change with a software replug. |
| `--hidhide hide\|show "<logfile>" "<topId>" "<id>"...` | Elevated helper: HidHide hide/show, then replug. |

Exit codes from the helpers: `0` = done; `3010` = pending until the device reconnects; anything else is a Win32 error code.

## Build, run, release

Use the .NET 9 SDK. Run these from the repository root.

```powershell
dotnet build GamepadMonitor -c Release                      # must finish with 0 warnings, 0 errors
dotnet run --project GamepadMonitor -c Release              # run the GUI
dotnet publish GamepadMonitor -c Release -o GamepadMonitor-release   # local copy the user's shortcuts point to
```

Release packages (both must exist for a GitHub release):

```powershell
dotnet publish GamepadMonitor -c Release -r win-x64 --self-contained true -p:PublishSingleFile=true -p:IncludeNativeLibrariesForSelfExtract=true -p:EnableCompressionInSingleFile=true -p:DebugType=none -o dist\full
dotnet publish GamepadMonitor -c Release -r win-x64 --self-contained false -p:PublishSingleFile=true -p:DebugType=none -o dist\small
```

Zip each folder (adding `LICENSE.txt` and `README.txt`) as `GamepadMonitor-<version>-win-x64.zip` and `GamepadMonitor-<version>-win-x64-small.zip`. Bump `<Version>` in the `.csproj` first, and put SHA-256 checksums in the release notes.

**Before publishing or replacing files, close any running copy** (`Get-Process GamepadMonitor | Stop-Process`). Otherwise the exe is locked and the publish fails or silently keeps the old file.

## How to verify a change

There is no unit-test project. Verify against real hardware:

1. **Build:** `dotnet build` with 0 warnings.
2. **Detection:** run `GamepadMonitor.exe --dump <file>` and read the report.
3. **UI:** start the app, then capture its window with `PrintWindow` (Win32), not a desktop screenshot, and look at the image. To select a list row in a script, use UI Automation (`SelectionItemPattern`).
4. **Report honestly.** Say exactly what you checked and what you couldn't. Anything that needs admin (enable/disable, replug, HidHide), a physical button press, or a controller that isn't connected can't be verified by an agent alone; tell the user what to click to test it.

## Safety rules (must follow)

- **Never disable, hide, replug or rumble the user's real controllers on your own initiative.** These change their hardware state, can trigger UAC prompts, and can break their games mid-session. Implement the feature and let the user trigger it, unless they explicitly ask you to run it.
- **Never put the event-log command lines in the UI, logs or commits.** Kernel-PnP event 225 includes the full command line of each blocking process, and these can contain secrets (for example, an editor's access token). Show program **names** only. `FindBlockers` already does this; keep it that way.
- **Privacy in screenshots and docs.** Device instance IDs can contain serial numbers or Bluetooth MAC addresses. Mask them (as in `docs/screenshot.png`) before anything goes into the repo or online. Don't commit personal paths, user names or emails.
- **Bluetooth rumble on Sony pads** switches the controller into "extended" mode until it reconnects, which can break DirectInput games. Keep the one-time warning dialog.
- **Don't add downloads or installers** (for example, auto-installing HidHide). The app may *open* the official HidHide releases page when the user clicks; installing is the user's job.
- **Don't commit or push without the user asking.**
- **End commit messages with** `Co-Authored-By: <your model name> <noreply@anthropic.com>` (or your own tool's equivalent attribution line).

## Code conventions

- **Language settings:** C# 12, `Nullable` and `ImplicitUsings` are **disabled**. Add explicit `using`s.
- **DPI:** the app is PerMonitorV2 DPI-aware. Wrap every pixel size in `D(...)` (scales by `DeviceDpi / 96`).
- **Theme:** dark, using the colors defined at the top of `MainForm` (`Bg`, `Card`, `Card2`, `Fg`, `Dim`, `Accent`, `Good`, `Warn`, `Bad`). Don't introduce new ad-hoc colors.
- **Text drawing:** use the `Text_` / `TextIn` helpers (`TextRenderer`). Always include `TextFormatFlags.NoPrefix`, or `&` in device IDs is swallowed as a mnemonic.
- **Threads:** raw-input and UI work happen on the UI thread. `XInputMonitor` and direct HID readers run on background threads. Lock `XSlot` objects, and marshal HID reports back with `BeginInvoke`.
- **Don't trust SetupAPI return codes alone.** A vetoed disable can come back as error 13 ("data is invalid") even though Windows marked the change. Always check the real device state (`Privileged.Probe`: ConfigFlags, problem code, `DN_STARTED`).
- **Grouping:** one physical controller is one `GamepadRow`. Enable, disable, hide and replug act on the row (top node or all members), never on a single child node.
- **User-facing text:** plain language. Say what happened and what the user should do; no jargon without explanation.

### Windows PowerShell 5.1 pitfalls

- **Encoding:** `Get-Content` / `Set-Content` default to the ANSI code page and **corrupt UTF-8** characters such as `●`, `·`, `—` and `→` that the source files use. Edit files with an editor tool, or use `[IO.File]::ReadAllText/WriteAllText` with UTF-8 (no BOM).
- **Chaining:** there are no `&&` or `||` operators. Use `;` or `if ($?) { }`.
- **Here-strings:** pass multi-line commit messages through a file (`git commit -F file`); piping a here-string to `-F -` doesn't work.
- **New installs:** after installing something with winget, refresh `PATH` in the current session or open a new terminal.

## Where to make common changes

| Goal | Where |
|---|---|
| Recognise a new controller type or name | `DeviceScanner.KnownNames`, `GameHwIds`, `XboxCompat` (Devices.cs) |
| Rumble for another brand | `HidDevice.Rumble` (+ `CanRumble`); add a decoder like `ParseSonyExtended` if output switches the input format |
| New column in the list | Column table in the `MainForm` constructor, plus `UpdateItem` |
| New card content in the live strip | `PaintInputs`, `DrawXInputCard`, `DrawHidCard` (MainForm.cs) |
| New elevated action | Add a branch in `Privileged.Dispatch` and `IsHelperCall`, then call it via `RunElevatedHelper` from the UI |
